# Поддержка документов в Гермесе

**Дата:** 2026-06-16  
**Статус:** Approved  
**Область:** `bot/hermes-bot.js`

## Цель

Добавить поддержку документов в Telegram-бота Гермес: принимать PDF, Word (.docx) и Excel (.xlsx), извлекать текст локально через npm-пакеты, суммаризировать содержимое и поддерживать Q&A по документу в рамках сессии.

## Архитектура

```
document message (PDF / docx / xlsx)
    ↓
bot.on('document', ctx)
    ↓
проверки: авторизация → онбординг → профиль → тип файла → размер (≤ 20 МБ)
    ↓
downloadUrl(telegramFileUrl)        // уже существует в боте
    ↓
parseDocument(buffer, mimeType)     // новая функция
  ├── pdf-parse   → text
  ├── mammoth     → text
  └── xlsx        → text (CSV-подобный)
    ↓
countWords(text)
    ↓
  ≤ 15 000 слов?
  ├── ДА  → сохранить в docContexts (Map chatId → text)
  │         суммаризировать → предложить Q&A
  └── НЕТ → обрезать до 15 000 слов + предупреждение
             суммаризировать → Q&A недоступен
    ↓
askAI(chatId, prompt)               // уже существует
    ↓
replyLong(ctx, summary)             // уже существует
```

## Новое состояние

```javascript
const docContexts = new Map(); // chatId → { text, fileName }
```

Хранит текст документа per chatId для использования в последующих вопросах. Сбрасывается при `/reset` или при получении нового документа.

## Парсинг по типу

| Формат | MIME | Пакет | Результат |
|--------|------|-------|-----------|
| `.pdf` | `application/pdf` | `pdf-parse` | Текст страниц |
| `.docx` | `application/vnd.openxmlformats-officedocument.wordprocessingml.document` | `mammoth` | Текст параграфов |
| `.xlsx` | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` | `xlsx` | Листы → CSV-подобный текст |

Прочие форматы (`.doc`, `.ppt`, `.csv`, изображения) → сообщение об ошибке.

## UX-сценарии

### Успех — короткий документ (≤ 15 000 слов)

1. Пользователь присылает файл
2. Бот: `📄 Читаю документ...`
3. Бот: краткое содержание от AI
4. Бот: `💬 Можешь задавать вопросы по документу.`

### Успех — длинный документ (> 15 000 слов)

1. Пользователь присылает файл
2. Бот: `📄 Читаю документ...`
3. Бот: `⚠️ Документ большой (~N слов), анализирую первые 15 000.`
4. Бот: краткое содержание от AI
5. Q&A недоступен (текст не сохраняется в docContexts)

### Q&A после загрузки документа

Когда `docContexts.has(chatId)` — в системном промпте `buildSystemPrompt()` добавляется контекст документа. Пользователь задаёт вопросы обычными сообщениями, бот отвечает с учётом содержимого файла.

При `/reset` — `docContexts.delete(chatId)` вместе с очисткой histories.

### Ошибки

| Ситуация | Сообщение |
|----------|-----------|
| Формат не поддерживается | `"Формат не поддерживается. Пришли PDF, Word (.docx) или Excel (.xlsx)."` |
| Файл > 20 МБ | `"Файл слишком большой (максимум 20 МБ)."` |
| Ошибка парсинга | `"Не удалось прочитать документ. Возможно, файл повреждён или защищён паролем."` |
| Пустой документ | `"Документ не содержит текста (возможно, это скан или защищённый файл)."` |

## Q&A через buildSystemPrompt

Функция `buildSystemPrompt(chatId)` расширяется: если `docContexts.has(chatId)`, в системный промпт добавляется блок:

```
Контекст документа (файл: <fileName>):
<text>
---
Пользователь может задавать вопросы по этому документу.
```

## Новые npm-зависимости

```bash
npm install pdf-parse mammoth xlsx
```

- `pdf-parse` — извлечение текста из PDF
- `mammoth` — конвертация docx в plain text
- `xlsx` — парсинг Excel-файлов

## Затронутые файлы

- `package.json` — 3 новые зависимости

## Что НЕ входит в эту задачу

- `.doc` (старый Word) — нет надёжного npm-парсера
- `.csv` — можно добавить позже (тривиально)
- Сканированные PDF (OCR) — требуют отдельного подхода
- Многостраничный чанкинг — для следующей итерации
- Сохранение документов между сессиями (перезапуск бота сбрасывает docContexts)
